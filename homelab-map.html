nbdevlab homelab

Two Proxmox servers and a bare-metal RAM node behind a WatchGuard Firebox on Starlink, with a third Proxmox host parked for now. They run the house services, a SIEM, a mail gateway and slerm, a Slurm cluster I built to learn Slurm end to end. Cloudflare, one Oracle VPS and Tailscale handle everything that comes in from outside, and one UPS decides what happens when the power goes out.

01 · Topology

The map

Every network hangs off the Firebox. Colored lines are the four networks, and each guest's short color stub says which one it sits on. Dashed lines at the top are outbound tunnels. The rails at the bottom show which PSU of each server is on UPS battery.

02 · Cluster

slerm

slerm is a Slurm cluster made of VMs on the Proxmox servers plus deadlock, built to learn Slurm end to end. The head runs Slurm, a control panel that submits and schedules jobs, and the NFS share every node mounts. Everything else is a Slurm job: NOAA radar processing, Wazuh alert analysis, software builds and local LLM serving.

LLM serving

Every LLM client talks to one OpenAI-style gateway on the head. The gateway starts a llama.cpp router on node04, which holds both Tesla P100s. A model that fits in their 32 GB runs on one card or across both. A bigger one keeps its overflow on node04's own CPUs. When nothing is asking, the model is unloaded and then the nodes power off. A request wakes them again.

03 · Power

Power failure

The UPS carries one PSU of each server. When it reports mains lost, ups-guardian on byteme2 sheds everything it can within four minutes. It keeps DNS and the tailnet router up so the lab stays reachable, and puts it all back when mains return.

04 · Outside

Public edge

How outside traffic reaches the lab and what the lab sends out. The website never talks to the house directly: the Worker reads the Pi's status API through a Cloudflare tunnel, and media goes through the VPS.

05 · Security

How it stays closed

The rules the layout above follows.

No inbound ports at home

Starlink's NAT sits in front of the Firebox. Everything that comes in rides a connection the lab opened itself: a Cloudflare tunnel, WireGuard to the VPS, or Tailscale.

The public box can't see the lab

The VPS is kept off the tailnet on purpose. Its WireGuard peers are locked down: one reaches only the Jellyfin VM, the other carries Wazuh agent traffic and nothing else.

Media sits in a DMZ

Jellyfin has its own VLAN, and the Firebox keeps it apart from every other segment.

Admin pages need a login first

Admin UIs on the web sit behind Cloudflare Access. Everything else is reachable only over the tailnet.

One SIEM sees everything

The hypervisors, servers and the VPS report to Wazuh. It blocks SSH brute force on its own and mails serious alerts out through PMG.

This page leaves things out

No addresses, port numbers, software versions or admin hostnames. The diagrams show how the lab is put together, not where to knock.
